# Aragora v2.12.0

**Status:** not released yet. The release date is the UTC date of the operator's `v2.12.0` tag; the release PR (#10560) writes it here, in `CHANGELOG.md` and in `aragora/__version__.py` on that day.
**Previous release:** v2.11.1 (release commit 2026-09-28, #10195, sha `486a10d8`; v2.11.1 was a patch on v2.11.0 and has no notes page)
**Release-candidate predecessor:** none (cut directly from `main`, as v2.11.0 was)

## Headline

Knowledge facts now belong to an organization. The v1 and v2 knowledge-base fact routes read, match and change only the caller's organization's facts, document ingestion carries the uploader's verified organization, and fact reads and writes without an organization fail closed instead of seeing every tenant's facts (#10298, #10386, #10555). Facts stored without an organization are quarantined until an operator assigns them. Isolation is not complete for every knowledge path yet: some Knowledge Mound paths are still scoped by workspace only, and the in-memory embedding store can return another organization's chunk text when two organizations store the same chunk id (see "Known issues / deferrals").

Permission failures now look like permission failures. Handler-level permission and role denials answer 403 instead of 500, MFA requirements answer 403 `MFA_REQUIRED`, and email, teams, cross-pollination, connector, analytics-platform, accounting and memory routes that were never dispatched now reach their handlers, with a 501 after the permission check where no backing logic exists yet (#10227, #10228, #10238, #10468, #10534, #10557).

The GitHub Action can be used from outside this repository again. A dangling `k8s` symlink, left when `deploy/k8s` was deleted on 2026-02-11, made GitHub's runner fail "Set up job" for every outside `uses: synaptent/aragora@<sha>`; v2.12.0 is the first tag with the fix (#10553).

The release PR (#10560) records here how many commits this release carries since the v2.11.1 release commit, counted at its final merge with `main`.

## What's new since v2.11.1

### Knowledge scoped to the organization
- Fact creation and import bind to the caller's organization; chunk search and Knowledge Mound fact sync stay closed; the `aragora knowledge` fact commands exit 2 (#10298)
- Organization-scoped fact persistence with a quarantine migration for facts without an organization (#10275)
- Ingestion, pipeline caches and chunk embeddings keyed by organization and workspace (#10386); fact routes served per organization with a uniform 404 (#10555)
- `/api/v1/index` routes answer instead of 500 (#10212); knowledge routes use RBAC v2 role permissions (#10224)

### Authorization and routing
- Middleware route rules for connector, analytics-platform, cross-pollination, teams, document-batch and memory routes; denials answer 403 (#10468, #10557)
- Previously unrouted email, teams, cross-pollination, connector, analytics-platform, accounting and memory handlers dispatched (#10227, #10228, #10238, #10473, #10479, #10534); flip, match and agent reputation detail reads served (#10306)
- Expired API keys rejected by the shared validator (#10530); five permission keys that handlers already checked registered (#10263)
- An ownership record grants access only within its own organization, and `POST /api/analytics/connect` requires `analytics.configure` (#10618)
- The memory handler binds each caller's auth context before its permission check, so a context left on the shared handler cannot answer for another caller (#10566)
- `aragora.tenancy.record_scope`, an organization-scope layer for tenant-owned records; no route uses it yet (#10282)
- Every automated merge path obeys the main-red halt (#10207)

### Structure
- Import-layer contract tranches T1-T6, which bring every top-level module into the contract, with `lint-run` enforcement (#10299, #10314, #10325, #10376, #10510, #10602, #10610, #10338) and `docs/architecture/IMPORT_LAYERS.md` (#10337); the receipt models, ODR JCS and oversight attestation move to `aragora.models.receipts`, with the old module paths aliased (#10512, #10590, #10592)
- P5 decomposition of the nomic, swarm, debate, CLI and pipeline modules behind their original import paths (see `CHANGELOG.md`)
- About 1,600 stale or fixed `.mypy-baseline` entries cleared (#10392, #10393, #10424, #10435) and the docs tree reorganized under a single `docs/README.md` index (#10349, #10351, #10352, #10353, #10354, #10356, #10357, #10364)

### SDKs, billing and fixes
- SDK and client methods for unserved routes removed (#9112, #10204, #10279, #10388); 139 stale contract-drift inventory rows resolved (#10475)
- Budget-guard ledger paths no longer depend on the working directory; metering guards its connection (#10210)
- Overlapping refreshes of the cached ODR signing key are serialized, so a load that began before a key rotation cannot replace the newer key (#10431); sync store migration and key rotation stay on one event loop (#10486); an encryption migration or key rotation that raises reports failure instead of success (#10606)
- Security floors for `pyjwt`, `urllib3`, `virtualenv`, `next`, `handlebars` and others (#10248, #10365, #10432, #10485)

Full grouped list: `CHANGELOG.md`, under `## [2.12.0]` once the release PR (#10560) moves the `## [Unreleased]` entries there.

## How this release is published

- **Before the tag.** The tag run's `docs-sync` job is blocking: the committed OpenAPI spec (`docs/api/openapi.json`, `docs/api/openapi.yaml`) and `docs/API_ENDPOINTS.md` must match their generators. Two pull requests that were still open when these notes were written merge on `main` first: the OpenAPI and API docs sync (#10604) and the release workflow fix (#10585). They are prerequisites of the tag, not changes these notes list.
- **The tag run.** The operator then tags `v2.12.0` on this release's merge commit. `release.yml` validates, tests and builds the wheel and sdist, and its `release` job creates and publishes the `v2.12.0` GitHub Release with those two files. Until #10585 merges, `release.yml` on `main` also has a `publish-pypi` job that uploads the built files to PyPI on every `v*` tag push; #10585 deletes that job, which is one reason it must merge before the tag. Once it has merged, the tag run does not upload to PyPI.
- **PyPI.** Once #10585 has merged, `publish-aragora.yml` is the only workflow that publishes `aragora` to PyPI. The operator dispatches it with `version=2.12.0` and `confirm=PUBLISH` only after the `release` job has finished and the GitHub Release shows its assets. Releases in this repository are immutable, so a release that `publish-aragora.yml` published first could no longer take the `release` job's files. `publish-aragora.yml` builds its own wheel and sdist, whose hashes can differ from the GitHub Release assets, and it retitles the existing release and replaces its notes.
- **SDKs** publish through their own workflows (see "SDK versions").

## Upgrade notes

### From v2.11.x or earlier

No server route is removed, but responses change; the sections below list what this release changes for callers. When coming from v2.10.x or earlier, also read the v2.11.0 and v2.10.0 tables under [Breaking Change Summary](../deployment/UPGRADE_ROADMAP.md#breaking-change-summary) in `UPGRADE_ROADMAP.md`. PyPI serves 2.11.1 until the operator pushes the `v2.12.0` tag and dispatches `publish-aragora.yml`; after that:

```bash
pip install --upgrade aragora==2.12.0
python -c "import aragora; print(aragora.__version__)"   # 2.12.0
```

### Knowledge deployments

- Every API caller that reads or writes knowledge facts needs an authenticated organization; without one it gets 403 `knowledge_org_required`.
- Facts stored before this release without an organization are quarantined. Follow "Legacy facts without an organization (operator-only)" in `docs/knowledge/KNOWLEDGE_MOUND_OPERATIONS.md` to assign them.
- Document chunks embedded before this release are keyed by workspace only and are not returned to organization searches until the documents are uploaded again.
- The `aragora knowledge` commands `query`, `facts`, `process` and `stats` exit 2 at the fact store, because the CLI has no authenticated organization.
- Organization isolation does not yet cover the Knowledge Mound paths or the in-memory embedding store named under "Known issues / deferrals". Read that entry before relying on isolation where organizations can share a workspace id or a chunk id.

### API clients

- Treat 403 on the routes named under "Authorization and routing" above as final; it replaces a 500 that clients may have retried.
- Previously unrouted routes without backing logic answer 501 `not_implemented` after their permission check.

### Budget guard

A relative `ARAGORA_DATA_DIR` or `ARAGORA_NOMIC_DIR` now resolves under the home directory. Before upgrading mid-month, copy the old `<working directory>/<dir>/budget_guard.json` to `~/<dir>/budget_guard.json` or set `ARAGORA_BUDGET_GUARD_STORE` to its absolute path; otherwise this month's recorded spend restarts at zero.

### GitHub Action users

`uses: synaptent/aragora@<sha>` fails "Set up job" in outside repositories at every commit from 2026-02-11 up to #10553, including the v2.10.0, v2.11.0 and v2.11.1 tags and the pin currently shown in the README. Pin the Action to the `v2.12.0` tag's commit once it exists. The README and setup-guide pins move to it in a follow-up PR after the tag.

### SDK versions

The TypeScript SDK (`sdk/typescript`, `@aragora/sdk`) and the Python SDK (`sdk/python`, `aragora-sdk`) move to 2.12.0 in this release, in lockstep with the platform. The minor bump covers their method removals: TypeScript `getMode`, `connectSSE`, `crossPollination.unsubscribe`, `apAutomation.addAPInvoice`, `policies.resolveViolation` and `AragoraClient.exportReplay`; Python `get_mode` and `connect_sse` (see each SDK's `BREAKING_CHANGES.md`). The SDKs publish through their own workflows (`publish-sdk-typescript.yml`, `publish-sdk-python.yml`), which the operator dispatches separately. Until then npm serves `@aragora/sdk` 2.11.1 (the `latest` dist-tag, published 2026-09-28T15:31Z) and PyPI serves `aragora-sdk` 2.11.0 (`info.version`, uploaded 2026-09-27T18:33Z), both read on 2026-10-10 from `https://registry.npmjs.org/@aragora%2Fsdk` and `https://pypi.org/pypi/aragora-sdk/json`. Neither contains these removals (npm 2.11.1 already carries the earlier #10138 removals).

## Known issues / deferrals

- **Knowledge isolation residuals (#10386):** the Knowledge Mound reads in `KnowledgePipeline.query` (the Mound items added to the answer context) and `KnowledgePipeline.query_mound` stay scoped by workspace only, and `process_document` and `process_text` still mirror documents, chunks and facts into the Mound by workspace only. The in-memory embedding store keeps each chunk's text under its chunk id alone: if two organizations store the same chunk id, the later write replaces the earlier one, and a search in the earlier organization can return the later organization's text. The v1 `/api/v1/knowledge/search` route stays closed and does not pass an organization. No production audit-session creator sets an `org_id`, so audit sessions still record a knowledge storage error, as before.
- **SDK registries** lag this release until the SDK publish workflows run (see "SDK versions").
- **v1 API:** this release does not change the v1 deprecation or its sunset handling. The 2026-06-01 sunset date that the deprecation docs and `Sunset` headers announce has passed; removing v1, or setting a new date, is a separate decision that this release does not make.

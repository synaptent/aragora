# Aragora v2.12.0

**Target release:** 2026-10-10, on the operator's `v2.12.0` tag
**Previous release:** v2.11.1 (release commit 2026-09-28, #10195, sha `486a10d8`; v2.11.1 was a patch on v2.11.0 and has no notes page)
**Release-candidate predecessor:** none (cut directly from `main`, as v2.11.0 was)

## Headline

Knowledge facts now belong to an organization. The v1 and v2 knowledge-base fact routes read, match and change only the caller's organization's facts, document ingestion carries the uploader's verified organization, and every reader or writer without an organization fails closed instead of seeing every tenant's facts (#10298, #10386, #10555). Facts stored without an organization are quarantined until an operator assigns them.

Permission failures now look like permission failures. Handler-level permission and role denials answer 403 instead of 500, MFA requirements answer 403 `MFA_REQUIRED`, and email, teams, cross-pollination, connector, analytics-platform, accounting and memory routes that were never dispatched now reach their handlers, with a 501 after the permission check where no backing logic exists yet (#10227, #10228, #10238, #10468, #10534, #10557).

The GitHub Action can be used from outside this repository again. A dangling `k8s` symlink, left when `deploy/k8s` was deleted on 2026-02-11, made GitHub's runner fail "Set up job" for every outside `uses: synaptent/aragora@<sha>`; v2.12.0 is the first tag with the fix (#10553).

This release carries the 240 non-merge commits since the v2.11.1 release commit, counted at the release PR's base `5529fb91`: fix 82, refactor 66, docs 35, chore 21, test 15, feat 10, ci 3, plus 8 commits titled with `[AGT-*]`/`[DIC-*]` work-item ids.

## What's new since v2.11.1

### Knowledge scoped to the organization
- Fact creation and import bind to the caller's organization; chunk search and Knowledge Mound fact sync stay closed; the `aragora knowledge` fact commands exit 2 (#10298)
- Organization-scoped fact persistence with a quarantine migration for facts without an organization (#10275)
- Ingestion, pipeline caches and chunk embeddings keyed by organization and workspace (#10386); fact routes served per organization with a uniform 404 (#10555)
- `/api/v1/index` routes answer instead of 500 (#10212); knowledge routes use RBAC v2 role permissions (#10224)

### Authorization and routing
- Middleware route rules for connector, analytics-platform, cross-pollination, teams, document-batch and memory routes; denials answer 403 (#10468, #10557)
- Previously unrouted email, teams, cross-pollination, connector, analytics-platform, accounting and memory handlers dispatched (#10227, #10228, #10238, #10473, #10479, #10534); flip, match and agent reputation detail reads served (#10306)
- Expired API keys rejected by the shared validator (#10530); five permission keys that handlers already checked registered (#10263)
- Every automated merge path obeys the main-red halt (#10207)

### Structure
- Import-layer contract tranches T1-T4b with `lint-run` enforcement (#10299, #10314, #10325, #10376, #10510, #10338) and `docs/IMPORT_LAYERS.md` (#10337)
- P5 decomposition of the nomic, swarm, debate, CLI and pipeline modules behind their original import paths (see `CHANGELOG.md`)
- About 1,600 stale or fixed `.mypy-baseline` entries cleared (#10392, #10393, #10424, #10435) and the docs tree reorganized under a single `docs/README.md` index (#10349, #10351, #10352, #10353, #10354, #10356, #10357, #10364)

### SDKs, billing and fixes
- SDK and client methods for unserved routes removed (#9112, #10204, #10279, #10388); 139 stale contract-drift inventory rows resolved (#10475)
- Budget-guard ledger paths no longer depend on the working directory; metering guards its connection (#10210)
- Security floors for `pyjwt`, `urllib3`, `virtualenv`, `next`, `handlebars` and others (#10248, #10365, #10432, #10485)

## Upgrade notes

### From v2.11.x or earlier

No server route is removed, but responses change. Read `### v2.12.0 Behavioral Changes` in [UPGRADE_ROADMAP.md](../deployment/UPGRADE_ROADMAP.md#breaking-change-summary), and the v2.11.0 and v2.10.0 tables when coming from older releases. PyPI serves 2.11.1 until the operator pushes the `v2.12.0` tag and dispatches `publish-aragora.yml`; after that:

```bash
pip install --upgrade aragora==2.12.0
python -c "import aragora; print(aragora.__version__)"   # 2.12.0
```

### Knowledge deployments

- Every API caller that reads or writes knowledge facts needs an authenticated organization; without one it gets 403 `knowledge_org_required`.
- Facts stored before this release without an organization are quarantined. Follow "Legacy facts without an organization (operator-only)" in `docs/knowledge/KNOWLEDGE_MOUND_OPERATIONS.md` to assign them.
- Document chunks embedded before this release are keyed by workspace only and are not returned to organization searches until the documents are uploaded again.
- The `aragora knowledge` commands `query`, `facts`, `process` and `stats` exit 2 at the fact store, because the CLI has no authenticated organization.

### API clients

- Treat 403 on the routes listed in the roadmap table as final; it replaces a 500 that clients may have retried.
- Routes listed without backing logic answer 501 `not_implemented` after their permission check.

### Budget guard

A relative `ARAGORA_DATA_DIR` or `ARAGORA_NOMIC_DIR` now resolves under the home directory. Before upgrading mid-month, copy the old `<working directory>/<dir>/budget_guard.json` to `~/<dir>/budget_guard.json` or set `ARAGORA_BUDGET_GUARD_STORE` to its absolute path; otherwise this month's recorded spend restarts at zero.

### GitHub Action users

`uses: synaptent/aragora@<sha>` fails "Set up job" in outside repositories at every commit from 2026-02-11 up to #10553, including the v2.10.0, v2.11.0 and v2.11.1 tags and the pin currently shown in the README. Pin the Action to the `v2.12.0` tag's commit once it exists. The README and setup-guide pins move to it in a follow-up PR after the tag.

### SDK versions

The TypeScript SDK (`sdk/typescript`, `@aragora/sdk`) and the Python SDK (`sdk/python`, `aragora-sdk`) move to 2.12.0 in this release, in lockstep with the platform. The minor bump covers their method removals: TypeScript `getMode`, `connectSSE`, `crossPollination.unsubscribe`, `apAutomation.addAPInvoice`, `policies.resolveViolation` and `AragoraClient.exportReplay`; Python `get_mode` and `connect_sse` (see each SDK's `BREAKING_CHANGES.md`). The SDKs publish through their own workflows (`publish-sdk-typescript.yml`, `publish-sdk-python.yml`), which the operator dispatches separately. Until then npm serves `@aragora/sdk` 2.11.1 and PyPI serves `aragora-sdk` 2.11.0; neither contains these removals (npm 2.11.1 already carries the earlier #10138 removals).

## Known issues / deferrals

- **`release.yml` on the tag push:** the workflow has failed on every tag push since v2.9.0-rc.1. On v2.11.1 it failed in `docs-sync` (`scripts/export_openapi.py` writes JSON into `docs/api/openapi.yaml`, so "Ensure docs are in sync" sees a diff), `release-checks` ("Skip baseline enforcement") and the `test` matrix ("Verify required test dependencies"). PyPI and the GitHub Release come from `publish-aragora.yml`. Regenerating the OpenAPI files to make `docs-sync` pass is out of scope for a release PR.
- **SDK registries** lag this release until the SDK publish workflows run (see "SDK versions").

# Aragora v2.11.0

**Target release:** 2026-09-25, on the operator's `v2.11.0` tag
**Previous release:** v2.10.0 (release commit 2026-09-04, #9977, sha `be07ea5b`)
**Release-candidate predecessor:** none (cut directly from `main`, as v2.10.0 was)

## Headline

The Open Decision Receipt moves to v0.2 and a stranger can check one without an account. ODR v0.2 records one verdict per reviewing issuer, dissent per finding with its severity, and the adjudication that settled a blocked review; it ships with a Draft v0.2 spec mapped against the two IETF receipt drafts, 15 deterministic test vectors with pinned verifier oracles, and `aragora-verify` 0.2.0, the first standalone verifier line that accepts v0.2. The server now exposes the trust surface without credentials: `GET /api/v2/receipts/{id}/export?format=odr` serves the canonical document and `POST /api/v2/receipts/verify` verifies a caller-supplied one statelessly. The first four signed PR receipts are published as the `receipts-2026-09-22` release, with a 60-second verification tutorial.

Dissent is now visible where it happens: every quorum run can post a non-counting advisory summary of each model family's verdict and severity-tagged findings. The Disagreement Atlas gains a pairwise agreement summary and a weekly regeneration job that publishes dated releases (`atlas-2026-09-13`, `atlas-2026-09-14`, `atlas-2026-09-21` so far).

This release carries 153 commits since the v2.10.0 release commit.

## Upgrade notes

### From v2.9.x (PyPI) or v2.10.0 (source)

The server API is additive. Read both `### v2.11.0 Behavioral Changes` and `### v2.10.0 Behavioral Changes` in [UPGRADE_ROADMAP.md](../deployment/UPGRADE_ROADMAP.md#breaking-change-summary): a PyPI user skips straight from 2.9.0 and picks up both. After the tag is cut:

```bash
pip install --upgrade aragora
python -c "import aragora; print(aragora.__version__)"   # 2.11.0
pip install --upgrade aragora-verify                      # 0.2.0 accepts ODR v0.2
```

### Receipt producers and consumers

- **The emitter now defaults to ODR 0.2** (#10165), as spec §9.5 planned for this release. This covers the CLI export, `aragora review`, the GitHub Action and `GET /api/v2/receipts/{id}/export?format=odr`. To keep emitting 0.1, pass `--odr-version 0.1`, request `?odr_version=0.1`, or set `ARAGORA_ODR_PROFILE_VERSION=0.1`. Every v0.1 document keeps verifying. `receipt export --acta` requires 0.2 and a usable signing key.
- **The GitHub Action can sign receipts** (#10163). The new `odr-signing-key` input takes an Ed25519 key from a repository secret; anyone with the matching public key can verify with `aragora-verify --pubkey`. There are new outputs `receipt-signed` and `receipt-key-id`, and the README pins the Action to a commit that has the input (#10168).
- `aragora-verify` 0.1.1 rejects v0.2 documents at `schema_conformance`; use 0.2.0. Without the optional schema extra, 0.2.0 enforces every constraint the bundled schema states, so a document 0.1.1 accepted can now fail (see `aragora-verify/CHANGELOG.md`).
- ODR documents are retrievable by receipt id without credentials; non-ODR export formats still require `receipts:read` and now answer 401 instead of 500.

### CLI and SDK consumers

- Gauntlet CLI: exit 0 means an unconditional PASS/APPROVED, exit 2 a conditional or review verdict, exit 1 a rejection, unknown verdict or non-completion.
- Python SDK: automatic waits stop at 60-second `Retry-After` hints; larger hints raise `RateLimitError`. TypeScript SDK: a premature socket close throws `ConnectionError` instead of a synthesized `debate_end`. Both SDKs removed methods on routes no server dispatched; see `sdk/python/BREAKING_CHANGES.md` and `sdk/typescript/BREAKING_CHANGES.md`.
- Imports of moved flat handler modules keep working through shims but emit `DeprecationWarning`.

## Known issues / deferrals

- **Hosted API:** `https://api.aragora.ai/readyz` answered `000` from outside on 2026-09-25; the Hetzner origin pack (#9882) is merged but the cutover on #9391 is an operator act.
- **Import cycles:** `mutual_import_cycles` is at its ceiling (140), so the next PR that adds a cycle fails the ratchet.

Fixed in this release: [UPGRADE_ROADMAP.md](../deployment/UPGRADE_ROADMAP.md) told operators to run `python -m aragora.migrations.runner migrate`, which exits 0 without applying anything because `aragora/migrations/runner.py` has no command-line entry point. It now uses the real CLI: `python -m aragora.migrations upgrade`, `downgrade [--target ID]` and `status`.
